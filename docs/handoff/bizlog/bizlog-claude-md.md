# BIZLOG — CLAUDE.md

## 1. 정체성
비즈로그(Bizlog) — 수십 명 이내 소기업·스타트업이 **자기 PC에 두고 쓰는**
회계·인사·경영관리 프로그램. 캐스트로그(castlog.kr)의 지급 확정 내역을 당겨와
로컬에만 있는 정보(계정과목·급여·직원 주민번호 등)와 결합해 쓴다.
대상 사용자: 대표·임원·회계담당 (노무사·세무사 없이 직접 처리하는 회사).

## 2. 기술 스택 (변경 금지)
- Python 3.12, SQLite 단일 파일 (`sqlite3` 표준 모듈 — ORM 없음)
- 암호화: `cryptography` (AES-GCM) + `argon2-cffi` (키 유도) + `keyring` (OS 키체인)
- 화면: 1단계 CLI(typer) → 필요 시 Streamlit. **`127.0.0.1`에만 바인딩**
- 엑셀: openpyxl · PDF: reportlab · 테스트: pytest
- 한국어 전용. 결제·클라우드 동기화·원격 접속 기능 없음.

## 3. 캐스트로그와의 경계 (최우선)
연동 계약 정본은 캐스트로그 레포 `docs/integrations/bizlog-contract.md`. 이 레포의
`docs/bizlog-contract.md`는 그 복사본이며, 어긋나면 캐스트로그 쪽이 맞다.
- **필드마다 원천은 하나.** `cl_*` 테이블은 캐스트로그 미러 — 임포터 외에는
  절대 UPDATE·INSERT 하지 않는다. 사람이 손대는 화면은 `cl_*`를 읽기만 한다.
- `biz_*` 테이블만 이 프로그램의 원천이다.
- 캐스트로그로는 **읽기 요청**만 보낸다. 쓰기(이체 완료·퇴사 통지)는 연동 토큰
  2단계가 열린 뒤, 그 스코프 안에서만.
- 매칭 키는 캐스트로그 ID(지급ID·전문가ID·프로젝트ID). **이름·주민번호로 매칭하지
  않는다.** 임포트는 멱등 — `INSERT … ON CONFLICT DO UPDATE`.

## 4. 주민등록번호 (이 프로그램은 보유한다 — 캐스트로그와 반대)
근거는 고용관계가 아니라 **법령**이다: 소득세법 §127·§164, 4대보험 각 법,
근로기준법 §41, 법인세법 §119(주식등변동상황명세서). 법령이 요구하는 범위에서만.
- 보유 대상은 **직원(`biz_employees`)과 주주(`biz_shareholders`)뿐.**
  전문가 주민번호는 절대 받지 않는다 — 캐스트로그가 지급명세서를 만들어 준다.
- 암호화 칼럼은 정확히 두 곳: `biz_employees.rrn_enc`, `biz_shareholders.rrn_enc`.
  스키마 테스트(`tests/test_schema_guard.py`)가 이 화이트리스트 밖의 주민번호
  칼럼·13자리 숫자 저장을 막는다.
- 평문은 DB·로그·엑셀·화면 상태 어디에도 남기지 않는다. 표시는 `rrn_masked`
  (`890101-1******`)만.
- **기본 경로는 조회가 아니라 문서 생성.** 복호화는 문서 생성 함수 안에서만
  일어나고 값은 함수 밖으로 리턴되지 않는다.
- 화면 임시 조회는 예외 경로: 사유 선택(목록) + 서술 필수 → 워터마크 → 30초 후
  재마스킹. 조회·생성 모두 `biz_access_logs`에 남긴다 (2년 보존).
- 키는 DB에 없다. 권한자 비밀번호에서 Argon2id로 유도한 키로 마스터키를 감싼다.
  권한자는 최소 2명(대표 + 회계담당). 비밀번호는 저장하지 않는다.
- 파기: 퇴직 후 3년(근로자명부) / 원천징수 관련 5년. `purge_due_at` 기준으로 매월
  목록을 띄우고 대표 확인 후 삭제.

## 5. 절대 금지 (Hard NO)
1. 주민번호·계좌 전체번호 칼럼을 §4 화이트리스트 밖에 만들기
2. `cl_*` 테이블을 임포터 외의 코드가 쓰기
3. 캐스트로그 원천 필드를 고치는 요청 보내기
4. 웹서버를 `0.0.0.0`에 바인딩하기, 원격 접속 기능 만들기
5. 암호화 키·비밀번호를 DB·설정 파일·환경변수·로그에 저장하기
6. 복호화된 주민번호를 함수 밖으로 리턴하기 (문서 생성 함수 내부에서만)
7. 지급명세서·원천징수 파일을 생성 후 프로그램이 보관하기 (생성 → 제출 → 삭제)
8. 전문가 주민번호를 받는 칼럼·임포트 경로 만들기
9. 캐스트로그 `service_role` 키를 이 프로그램에 두기
10. `biz_employees`와 `cl_experts`를 조인하기

## 6. 항상 (Always)
1. 새 테이블 → `cl_`/`biz_` 접두어로 원천 명시
2. 임포트 → `biz_import_logs` 기록 (파일명·건수·시각)
3. 주민번호 복호화 → `biz_access_logs` 기록 (누가·언제·사유·문서종류)
4. 새 문서 양식 → `rrn_required` 플래그 기본 `False`
5. 퇴사 처리 → 후임 래핑 추가 → 퇴사자 래핑 폐기 → 비밀번호 교체 + 재암호화,
   이 순서를 코드가 강제
6. 새 화면 → 엑셀 내보내기 시 주민번호 칼럼 제외 확인
