# 전문가 상시 활용 기능 설계 (2026-08-16)

전문가가 캐스트로그 가입 기업과의 섭외 업무 외에도 평소 사용할 수 있는 기능들의
설계. 사용자 지시로 아래 항목을 설계·구현 대상으로 확정한다. §5(민감정보)·§4
(전문가 소유 데이터)·§14(운영 원칙) 준수.

---

## A. 외부 송신 (사용자 요청 #3 — 방식 확정)

**배경**: 전문가들이 현재는 이메일에 **첨부파일을 직접 보내** 이력서/신분증사본/
통장사본을 캐스트로그 비가입 기업·기관 담당자에게 전달한다.

**채택 방식 — 서명된 만료 다운로드 링크(첨부 아님)**
- 이유: 신분증·통장사본은 민감서류다. §5는 **공개 URL 금지, 서명된 만료 URL만**
  허용한다. 첨부는 수신함에 영구 잔존·재유포·회수 불가라 부적합.
- 링크 방식이 실제로 더 효율적: 한 번에 여러 서류를 보내고, **만료·회수·열람기록**이
  된다. 수신자는 링크 클릭 → 다운로드(전문가의 기존 UX와 동일한 체감).

**설계**
- 조합 발송: 이력서 / 신분증사본 / 통장사본 중 선택(전문가가 보유한 서류만).
- 기본 만료 72시간, 1회 재발송·즉시 만료(회수) 가능.
- `expert_external_sends`(전문가 소유, RLS 본인): recipient_email·name,
  document_types[], event_name·org_name·memo, sent_at, expires_at, status,
  opened_at(열람 시각). 링크는 만료 서명 URL(스토리지) 또는 토큰 경유.
- 발송 이메일은 플랫폼 발송 경로(넥스트랩)로. sms/email 로그 기록.
- 페이지: 발송 폼 + 발송 내역 리스트(메모 편집: 행사명·의뢰기관·용도).
- 추가 아이디어: 수신 확인(열람 알림), 조합 프리셋 저장, 발송 전 미리보기,
  수신자별 워터마크(신분증·통장).

## B. 상시 활용 기능 (사용자 요청 #4 — 1·2·5·6·7 설계)

### 1. 공개 프로필 / 미니 이력서 (공유 링크·QR)
- 전문가가 공개 범위를 고른 프로필(전문분야·경력·소개·대표 실적)을 **공개 링크**로.
- 라우팅: 공개 전용 짧은 경로(예약 슬러그 규칙 준수, 예: `/p/{handle}`) — 테넌트 밖.
- 전문가가 공개 on/off·항목 선택. 민감정보(주민번호·연락처·서류)는 절대 미포함.
- QR 생성(오프라인 명함·행사용). 조회수 집계(선택).
- 테이블: `expert_public_profiles`(handle, visible_fields, is_public, ...). RLS 본인 편집.

### 2. 활동 캘린더 (iCal 내보내기)
- 섭외(활동기간)·수락 프로젝트·지급 예정/완료 일정을 한 화면 캘린더로.
- 데이터는 기존 테이블에서 파생(신규 저장 최소). 월/리스트 뷰.
- **iCal(.ics) 내보내기** 라우트로 개인 캘린더 구독. 회신 마감일시도 이벤트로.

### 5. 경력/실적 아카이브 (포트폴리오)
- 프로젝트별 역할·기간·후기·산출물 링크를 전문가가 정리(전문가 소유).
- 공개 프로필(#1)과 연동: 선택 항목만 공개.
- 테이블: `expert_portfolio_items`(title, role, period, summary, links[], is_public).
  RLS 본인. 산출물 원본은 저장 안 함(외부 링크 원칙 §6).

### 6. 알림함 (통합 알림 + 읽음 관리)
- 섭외 요청/응답, 지급 확정/완료, 주민번호 조회, 서류 만료 등 알림 통합.
- 테이블: `expert_notifications`(type, title, body, link, read_at, created_at).
  RLS 본인. 각 이벤트 훅에서 insert(연동 로직은 lib/integrations).
- 포털 헤더에 미읽음 뱃지. 목록 화면 + 읽음 처리.

### 7. 문의 / 지원 요청 (티켓)
- 전문가가 플랫폼(넥스트랩) 또는 연결 기업에 문의 티켓 생성.
- 테이블: `expert_support_tickets`(subject, body, target(platform|tenant),
  status, created_at). RLS 본인 + 대상. 상태(접수·처리중·완료).
- 기존 platform_inquiries와 구분(그건 도입 문의). 이건 로그인 전문가용.

### (부가) 서류 만료 알림 — #6과 연계
- 신분증·통장 등 갱신 리마인더를 #6 알림함으로 발송.

---

## 구현 순서(제안)
1. **외부 송신(A)** — 독립 기능, 즉시 유용.
2. **알림함(6)** — 다른 기능들의 알림 허브가 되므로 먼저.
3. 공개 프로필(1) + 포트폴리오(5) — 연동.
4. 활동 캘린더(2), 문의(7).

각 단계는 마이그레이션(전문가 소유·RLS)→서버 액션→UI→탭/링크 순으로 빌드하고,
빌드·실동작 확인 후 보고한다(§14-7·14-8).
