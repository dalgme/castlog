# AI 보조기능 파급력 순위 & 섭외 운영 워크플로우 — 구현계획 정리

- 상태: 초안(사용자 피드백 반영본) · 확정 대기 항목 표시(⚠︎)
- 작성 근거: 대표 피드백(AI 보조기능 파급력 순위 3건) + 대화 전수 점검
- 설계문서 매핑: 4장(전문가 신원), 5장(민감정보), 7장(전자결재), 8장(워크플로우), 14장(운영·AI 경계)
- 관련 모듈: `experts`(주), `operations`·`approvals`(연동). 서버 모듈 게이트 `requireModule` 필수.

> **AI 경계 재확인(CLAUDE.md 14.1 / Hard NO 2·11).** AI(Anthropic API)는 **설명·보완·문장화·검수**만 담당한다.
> 권한·결재 승인·지급 확정·데이터 판정의 근거로 AI 응답을 쓰지 않는다. 아래 ②·③ 피드백은 대표가 **"AI를 쓰지 말라"**고
> 명시했으므로 **AI 기능이 아니라 사람이 통제하는 정형 워크플로우**로 구현한다. 이 문서는 그 구분을 명시적으로 유지한다.

## A. 대표 피드백 3건 → 구체 구현 (대체/보완 정리)

### ① (AI) 전문가 후보 제시 + 섭외 사유 초안  ↔  (신규) 프로젝트 종료 필수 평가 → 지급품의 게이트
- **AI 보조(유지, 파급력 1위):** 전문가 풀에서 분야·이력·**과거 평판**으로 후보를 제시하고 섭외 사유 초안을 생성 → 담당자 검토시간 단축.
  AI는 **추천·초안까지만**, 섭외 결정·비용은 사람이 확정(경계 준수).
- **신규 필수 기능(평판 데이터의 출처):**
  - 각 프로젝트 **종료 시 책임담당자가 해당 프로젝트에 참여한 전문가별 평가 입력**:
    - **평가 점수: 10점 만점, 필수 입력**
    - **평가 이유: 선택 입력**
  - **게이트:** 참여 전문가 전원의 평가가 입력되지 않으면 **전문가 수당 지급품의서 작성 불가**(서버 강제).
    (기존 `단계 12` 지급품의 진입 조건에 평가완료 체크 추가)
  - **가시성(테넌트 격리, 설계문서 4장):** 이 평가는 **전문가 본인에게 노출 금지**, **조회하는 회사(테넌트)만** 열람.
    평가는 `expert_tenant_links` 범위 안의 테넌트 귀속 데이터로, 교차 노출 절대 금지.
  - 평가 이력은 ①의 AI 후보 제시에서 **평판 근거**로 활용(테넌트 격리 유지 — 자사 평가만).
- **데이터:** `expert_evaluations`(tenant_id, project_id, expert_id, score 1–10, reason nullable, evaluator_id, created_at) + RLS(테넌트, 전문가 SELECT 차단).
- **감사:** 평가 입력·수정은 `audit_logs` 기록.

### ② (AI) 회신 서식·이미지에서 서명·금액·세무구분 추출  →  (대체) 전문가 서명·날인 등록 + 수락서 자동 서명
- **AI 추출은 채택하지 않음.** 대신 **사람이 만든 정형 서명 파일**을 사용:
  - 전문가가 등록 페이지에서 **서명(날인) 파일 업로드**, 또는 **모바일에서 직접 손서명 → 파일 저장**
    (스택의 `react-signature-canvas` 활용, 이미지 리사이즈 파이프라인 경유, 암호화 버킷 보관 — 설계문서 5·6장).
  - **(강사)섭외수락서** 화면: 전문가가 내용을 확인하고 **"확인 완료 및 서명"** 버튼 클릭 → **등록된 서명(날인)이 자동으로 첨부되어 송신**.
- **데이터:** `expert_signatures`(전역 테이블, 전문가 소유 — 서명 파일 참조·암호화), 수락서 발송/서명 이력 `recruitment_acceptances`.
- **모바일 완전 대응(설계문서 10장 최우선).**

### ③ (AI) 통화 후 음성 → 구조화된 섭외 기록  →  (대체) 사람이 통제하는 섭외 실행·수락·취소 워크플로우
- **AI로 섭외기록을 남기지 않는다(명시).** 정형 버튼·강제 입력으로 처리:
  - **섭외 요청 발송:** 조회된 강사/멘토에게 **"섭외요청 이메일/문자 보내기"** 버튼으로 송신
    (기존 `단계 14` 발송 인프라·발송유형 분리 재사용 — 업무연락).
  - **직접(전화) 섭외 수락:** 담당자가 구두 승인받은 경우 **"직접 수락 확인"** 버튼 → **작은 팝업으로 구조화 입력 강제**:
    - **통화 일시**(월/일 + 몇 시경) — 간단 구조화 입력
    - **섭외 메모**(선택)
    - **처리 직원 자동 기록**(누가 "직접 수락 확인"했는지 = 통화시간/메모 작성자)
  - **섭외 취소(가장 긴급):**
    - 전문가 셀프: **"섭외 취소"** 버튼 → 간단 사유 입력 → 시스템 취소.
    - 전화·문자 취소: 담당자가 **"직접 수락 취소 확인"** 버튼 → 팝업(통화시간/메모) → 취소 적용.
    - **전사 긴급 알림:** 자동·수동 취소 모두 **모든 임직원 대시보드에 "취소 알림" 경고** 표시,
      **프로젝트 담당자가 "확인 완료"를 누를 때까지 유지**.
    - **취소 내역 리스트:** 프로젝트별 / 월별 / 연간별로 조회·관리(엑셀 내보내기 고려 — Always #6).
- **데이터:** `recruitment_requests`(발송/직접), `recruitment_actions`(수락·취소, 채널=발송/직접, 통화일시·메모·처리직원),
  `recruitment_cancellations`(사유·유형=자동/수동·확인상태·확인자·확인시각). 전부 tenant_id + RLS + `audit_logs`.
- **연동:** `operations`(프로젝트 배정) ↔ `experts`. 취소 알림은 공통 기반(대시보드·발송)에 얹음.

## B. AI 보조기능 — 파급력 순위(정리본)

> 1~3위는 대표가 제시한 원본. **4~10위는 이전 제안의 재구성 초안(⚠︎ 원본 목록과 대조 필요)** — 확정 전 검토 요망.
> 전 항목 **AI 경계 준수**: 근거·판정에 사용 금지, 산출물은 사람이 확정. 프롬프트는 버전관리·롤백(14.1).

| 순위 | 기능 | AI 역할 | 경계/처리 |
|---|---|---|---|
| 1 | 전문가 후보 제시 + 섭외 사유 초안 | 추천·초안 | 결정·비용은 사람. 평판은 자사 `expert_evaluations`만(격리) |
| 2 | (대체됨) 서명·금액·세무구분 추출 → **서명 등록/자동서명(비-AI)** | 없음 | A-② 참조. AI 미사용 |
| 3 | (대체됨) 음성→섭외기록 → **정형 섭외/취소 워크플로우(비-AI)** | 없음 | A-③ 참조. AI 미사용 |
| 4 ⚠︎ | 결과보고서·완수보고서 초안·문장 다듬기 | 문장화·보완 | 컨설턴트 role에 AI 보완본 노출 금지(Hard NO 2). 검수는 권한자 |
| 5 ⚠︎ | 제안서·견적서 검수/보완 제안 | 검수·제안 | 확정은 사람. 원문 근거 표기 |
| 6 ⚠︎ | 품의서 사유문 초안 도우미 | 초안 | 승인 근거로 사용 금지. 결재는 라인대로 |
| 7 ⚠︎ | 만족도 설문 자유응답 요약·분류 | 요약·분류 | 통계는 사업연도 축. 원문 보존 |
| 8 ⚠︎ | 프로젝트 21단계 지연·리스크 브리핑 | 요약 | 상태 판정은 시스템 규칙. AI는 설명만 |
| 9 ⚠︎ | 전문가 서류 결측·불일치 안내 | 문서 이해·안내 | 조회는 열람통제/로그 준수(5장). 판정은 사람 |
| 10 ⚠︎ | 발송 문안 생성·톤 교정 | 문장화 | 광고성/업무연락 유형·수신거부 규칙은 시스템 강제(5-1) |

기존 계획 매핑: `단계 25(AI 개입 포인트 설계)` = 위 표의 게이트·경계 확정 + 프롬프트 버전관리 구현. `단계 26(AI 음성 PoC)`은
임원 업무보고/지시용으로 유지하되, **섭외기록에는 음성/AI 미적용**(③에서 분리)임을 명확히.

## C. 대화 전수 점검 — 계획 미반영 항목(신규 편입)

1. **[운영/배포] 프로덕션 Supabase 정합 근본 수정** — 라이브(castlog-seven / castlog.kr)가 옛 빌드 + 잘못된
   `NEXT_PUBLIC_SUPABASE_URL`(현 castlog 프로젝트 `tvltecsvtozijotmcoqs` 아님)로 인증 → 로그인 불가.
   조치: Vercel Production/Preview env를 `tvltecsvtozijotmcoqs`로 정합 후 **재빌드**(NEXT_PUBLIC은 빌드타임 주입) →
   최신 브랜치 프로덕션 승격. env 스코프 위생 점검을 런북에 추가. (진행: 사용자 대시보드 조치 대기)
2. **[auth] 최초 로그인 시 비밀번호 강제 변경** — `단계 5` 후속 과제로만 언급되어 미편입. 정식 단계로 편입.
3. **① 전문가 평가·평판 게이트**(A-① 신규) — 계획 미존재.
4. **② 서명·날인 등록 + 수락서 자동 서명**(A-②) — 계획 미존재.
5. **③ 섭외 실행·수락·취소 + 전사 긴급 취소 알림 + 취소 내역**(A-③) — 기존 `단계 11`을 확장.
6. **AI 파급력 순위·경계 표**(B) — `단계 25`에 구체 근거로 편입.

(이미 계획에 있는 것: 데이터 자가보관(20), 네이버웍스(21), 데이터레지던시/국내메일(다음과제), 출장품의(22),
종료 기여도+종료품의 게이트(23), 임원 대시보드(24) — 유지.)

## D. 신규/확장 빌드 단계 (초안 번호 — 우선순위는 대표 확인)

- **단계 27 · 전문가 평가·평판 → 지급품의 게이트** (experts↔approvals) — A-①
- **단계 28 · 전문가 서명·날인 등록 + (강사)섭외수락서 자동 서명·발송** (experts) — A-②
- **단계 29 · 섭외 실행·수락·취소 워크플로우 + 전사 긴급 취소 알림 + 취소 내역** (experts↔operations) — A-③
- **단계 30 · 최초 로그인 비밀번호 강제 변경** (공통 기반/auth) — C-2
- **단계 25 확장 · AI 개입 포인트 = 파급력 순위/경계 확정 + 프롬프트 버전관리** — B

> ⚠︎ 확인 요청: **B의 4~10위는 재구성 초안**입니다. 원본 "10가지" 목록을 주시면 표를 원본에 맞춰 교정하겠습니다.
