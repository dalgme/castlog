# 이메일 데이터레지던시 판정 + 국내 벤더 매트릭스 (2026-08-12)

트랜잭션·알림 이메일 발송 경로를 국외(Resend/AWS SES) → 국내로 전환할지에 대한
판정 기록. CLAUDE.md 2장(기술스택 확정: 이메일=Resend)과 14장(데이터레지던시·
국외이전) 사이의 충돌을 §14-9(외부 가이드 유입 시 충돌 판정) 절차로 정리한다.

---

## 1. 배경 — 왜 재검토하나

- CASTLOG는 **한국 전용 B2B SaaS**로 개인정보(성명·연락처·지급 안내·서류 요청
  링크 등)를 이메일로 발송한다.
- 현행 발송 제공자 **Resend는 미국 인프라(AWS SES 계열)** 기반이다. 개인정보가
  포함된 메일이 미국 사업자를 경유·보관되면 **개인정보보호법 제28조의8
  (개인정보 국외 이전)** 적용 대상이 될 수 있다.
- 이미 `tenant-data-residency.md` §7.2에서 백업 목적지에 대해 동일한 국외이전
  리스크를 지적하고 **(a) 국내 제한(권장)** 을 채택했다. 이메일 발송 경로도
  같은 기준을 적용하는 것이 일관적이다.

## 2. §14-9 충돌 판정

| 항목 | 내용 |
|---|---|
| 기존 확정 | CLAUDE.md 2장 "이메일: Resend" (스택 변경 금지) |
| 유입 요구 | 국내 데이터레지던시 준수를 위한 Resend→국내메일 교체(단계 27) |
| 충돌 성격 | 스택 고정값 vs 법적 리스크(국외이전). **부분 충돌** |
| 판정 | **조건부 채택** — 아래 3항 |

### 판정 상세
1. **즉시 스택을 일방 교체하지 않는다.** Resend를 기본 어댑터로 유지한다.
   (스택 변경은 §13 승인 게이트 대상. 발신도메인 인증(SPF/DKIM/DMARC) 재설정과
   벤더 계약이 선결되어야 실동작하므로, 코드만 바꿔선 완결 불가 — 더미 금지 §14-7.)
2. **교체를 "설정화"한다(§14-2).** 발송 수단을 어댑터(`lib/email/provider.ts`)
   뒤로 격리하고 `EMAIL_PROVIDER` 환경변수로 선택하게 한다. 이로써 국내 제공자
   전환이 `send.ts` 수정 없이 설정+어댑터 추가만으로 가능해진다(BYO SMS 패턴 §5-2).
3. **국내 어댑터는 자격증명·발신도메인 인증 확보 후 추가한다.** 미검증 벤더
   API를 "연결된 척" 넣지 않는다(§14-7). 그 전까지 미구현 제공자 지정은 테스트
   모드(기록만)로 강등된다.

→ 결과적으로 단계 27의 "교체"는 **교체 준비(어댑터 seam) + 벤더 선정 근거(본 문서)**
   까지 이번에 완료하고, **실 전환은 벤더 계약·도메인 인증·사용자 승인 후** 수행한다.

## 3. 국내 이메일 벤더 매트릭스

> ⚠️ 검증 한계: 이 환경은 다수 벤더 도메인 egress가 제한되어 **공식 문서를 직접
> 열람하지 못했다.** 아래는 일반적으로 알려진 특성 기반 정리이며, **벤더 선정 전
> 각사 공식 문서로 리전·API 계약·요금·발신자 인증 요건을 재확인**해야 한다.
> (동일 한계를 tenant-data-residency.md §5·§8에서도 명시.)

| 벤더 | 유형 | 국내 리전 | 트랜잭션 API | 발신자 인증 | 적합 용도 | 비고 |
|---|---|---|---|---|---|---|
| **NHN Cloud (Email)** | IaaS 부가 | 예(국내) | REST(appKey/secretKey) | SPF/DKIM 등록 | **트랜잭션·대량** | 국내 클라우드, PIPA 친화. **1순위 후보** |
| **다우기술 / 자몽(gabia 계열 등)** | 메일 SaaS | 예(국내) | REST | SPF/DKIM | 대량·뉴스레터 | 국내 발송 실적 다수 |
| **스티비(stibee)** | 마케팅 메일 | 예(국내) | REST | SPF/DKIM | **광고성·뉴스레터** | 트랜잭션보다 마케팅 특화 |
| **알리고(email)** | 발송대행 | 예(국내) | REST | 발신주소 등록 | 트랜잭션·알림 | 이미 SMS 후보(§5-2)라 운영 일원화 이점 |
| **카카오 알림톡/친구톡** | 메시징 | 예(국내) | REST(BYO 채널) | 채널·템플릿 심사 | 알림(비-이메일) | 이메일 대체 채널로 병행 검토 |
| Resend (현행) | 트랜잭션 | **아니오(미국)** | REST(Bearer) | SPF/DKIM | 트랜잭션 | **국외이전 리스크** — 교체 대상 |
| Mailgun/SendGrid | 트랜잭션 | 아니오(해외) | REST | SPF/DKIM | 트랜잭션 | Resend와 동일 국외 리스크 |

### 권고
- **트랜잭션(업무 알림·인증·서류/지급 안내): NHN Cloud Email 1순위.** 국내 리전 +
  성숙한 REST API + 발신도메인 인증 지원. 알리고는 SMS와 운영 일원화가 강점이라
  차순위.
- **광고성(뉴스레터·신규기회 홍보): 스티비** 병행 검토(마케팅 기능 특화). 단,
  광고성은 CLAUDE.md 5-1 강제(수신거부·(광고)표기·미동의 제외)를 발송 계층에서
  이미 처리하므로 벤더는 순수 전송만 담당.

## 4. 이번 반영 범위 (코드)

- 신설 `lib/email/provider.ts` — `EmailProvider` 인터페이스 + `ResendProvider`
  (현행 기본) + `resolveEmailProvider()`(EMAIL_PROVIDER 기반 선택).
- `lib/email/send.ts` — 인라인 Resend fetch 제거, 어댑터 호출로 전환.
  발송 정책(광고 필터·수신거부 삽입·email_logs·usage 계측)은 그대로.
  발신주소 env를 `EMAIL_FROM`(신규) → `RESEND_FROM`(하위호환) 순으로 해석.
- 기본 동작 불변: `EMAIL_PROVIDER` 미설정 = resend, `RESEND_API_KEY` 사용 →
  기존과 100% 동일. 빌드 그린 확인.

## 5. 실 전환 시 남은 작업 (승인·자격증명 필요 — 미완료로 명시)

1. 벤더 최종 선정(공식 문서 재확인) + 계약·API 키 발급.
2. 발신 도메인(castlog.kr) SPF/DKIM/DMARC를 선정 벤더 기준으로 재설정.
3. `provider.ts`에 국내 어댑터 클래스 추가(`resolveEmailProvider` 분기) —
   실제 API 계약 확정 후. **미검증 상태로 추가 금지(§14-7).**
4. 스테이징에서 실발송 검증(트랜잭션·광고성 각 1건) 후 `EMAIL_PROVIDER` 전환.
5. 개인정보처리방침·국외이전 고지 갱신(국내 전환 완료 시 국외이전 항목 정리).

## 6. 남은 리스크 / 미해결
- **OTP SMS는 별개**: 전문가 인증 OTP는 넥스트랩 솔라피(§5-2)로 이미 국내 발송.
  본 문서는 **이메일**에 한정한다.
- 벤더 리전·API 세부는 egress 차단으로 미검증(§3 경고). 선정 단계에서 필수 확인.
