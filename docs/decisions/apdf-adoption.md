# APDF 가이드 반영 판정 기록 (2026-07-30)

APDF Automation Solution MVP(AI Platform Development Framework)의 원칙을
CASTLOG 확정 기획과 대조하여 채택/제외를 판정한 기록.
채택분은 CLAUDE.md 14번 절에 규칙으로 반영되었다.

## 채택 (CLAUDE.md 14번 반영)

| APDF 원칙 | 반영 방식 |
|---|---|
| AI는 설명·개인화 담당, 핵심 판정은 검증 가능한 로직 | AI 경계 규칙 — AI를 권한·결재·지급 판정의 근거로 사용 금지 |
| AI 응답을 권한·안전 판정의 단일 근거로 사용 금지 | 위와 동일 규칙으로 통합 |
| 소수 운영자가 코드 수정 없이 반복 운영 | 운영 설정화 규칙 — 자주 바뀌는 값 하드코딩 금지 |
| 위험 작업 2단계 확인 + 권한 분리 | 위험 작업 보호 규칙 |
| 삭제보다 비활성화·익명화·복구 가능 우선 | 채택 + 예외 명시(법정 보존기간 경과 민감정보 자동 파기가 우선) |
| 캠페인·설정의 미리보기·예약·중지·롤백 | 발송 인프라(단계 14) 요구사항으로 반영 |
| 운영 설정 draft/publish/rollback | 전결규정·발송 템플릿 등 운영 설정 버전 관리로 반영 |
| 디자인 토큰·컴포넌트 계약으로 잠금, 시안 임의 재해석 금지 | 디자인 잠금 규칙 (기존 브랜드 토큰 규칙 강화) |
| 모바일을 데스크톱 축소판으로 구현 금지 | 기존 10번(역할별 반응형)에 통합 |
| 더미 버튼·가짜 인터랙션을 완료로 보고 금지 | 더미 구현 금지 규칙 |
| 승인되지 않은 다음 단계 시작 금지 | 단계 승인 게이트 — 단계 완료 보고 → 승인 → 다음 단계 |
| 모든 핵심 행동 이벤트 저장 / 관리자 행동 감사로그 | 기존 audit_logs 규칙(7·12번)과 일치 — 유지 |
| 문서 충돌 점검(Sprint 0 정합성 감사) | 신규 외부 가이드 유입 시 충돌 판정 기록을 남긴다 (본 문서가 선례) |
| QA Critical Gate(승인 범위·실동작·테스트 증거·디자인·모바일·위험 작업 보호) | 단계 완료 보고 체크리스트로 반영 |

## 제외 (기획 충돌)

| APDF 항목 | 제외 사유 |
|---|---|
| 결제·상품, 이벤트·쿠폰·할인 모듈, 수익모델 설계 | CLAUDE.md Hard NO 11 — 결제·PG 코드 금지. 모듈 조합은 계약 정보일 뿐 |
| 유입→체험→유료전환 퍼널, 셀프 가입 여정 | 셀프 온보딩 없음 — 테넌트는 플랫폼관리자 수동 생성 (설계문서 7.1) |
| SEO/GEO/AEO·마케팅·UTM 모듈 | 인증 기반 B2B 내부 도구. 공개 화면은 랜딩뿐 — 랜딩 기본 메타만 유지 |
| 12개 공통 운영 모듈 체계 | CASTLOG 확정 모듈 구조(공통 기반 + experts/approvals/operations 3축)와 충돌 — 기존 구조 유지. 로그·감사·Feature Flag는 이미 공통 기반에 존재 |
| Sprint 0~5 재편 | Phase 1 실행계획서 단계 1~19로 이미 진행 중 — 일정 체계 재편은 혼선. 프로세스 원칙(승인 게이트·더미 금지)만 채택 |
| AI Console(관리자 프롬프트 편집) | 요구사항에 없는 기능 — Hard NO 정신(범위 외 기능 추가 금지). 단, AI 설정 버전·롤백 원칙은 향후 AI 보고서 보완 기능에 적용 |
| 100점 평가 체계(점수제 QA) | 소규모 단계 진행과 안 맞는 오버헤드 — Critical Gate(이진 판정)만 채택 |
| Visual Regression 필수화 | Phase 1 범위 초과 — 안정화 단계(단계 16 이후) 선택 도입 항목으로 보류 |
