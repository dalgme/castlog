# 전문가 섭외 라이트 모드 (experts_lite)

- 판정일: 2026-08-25
- 상태: 채택 (기획 확정 — 사용자 지시 "라이트 모드 구현, 각 사용기업이 스스로 설정")
- 저장: `tenants.feature_flags.experts_lite` (boolean, 기본 false — 마이그레이션 불요)

## 무엇인가

experts 모듈의 **운영 방식 옵션**이다. 회사가 적법 보유한 전문가 명단으로
섭외 현황·일정 중복·후보 순위만 관리하고, 전문가와의 온라인 접점(발송·동의
링크·포털 서명)은 쓰지 않는다. 확정은 전화 등으로 직접 확인한 뒤 수동
'섭외 완료(수락서 생성)' 버튼으로 한다.

## 왜 모듈이 아니라 플래그인가

- 모듈 조합은 계약(플랜) 정보라 캐스트로그 승인이 필요하다.
  라이트 모드는 **기능 축소**라 계약에 닿지 않는다 → 기업이 스스로 설정
  (설정 > 기업관리 > 전문가 섭외 운영 방식, `modules` 위임 스코프).
- 별도 테이블·별도 상태 모델을 만들지 않는다. 같은 `expert_engagements`를
  쓰므로 라이트 ↔ 풀 전환 시 데이터가 그대로 이어진다 (CLAUDE.md §1-2-8).

## 무엇이 바뀌나

| 영역 | 라이트 모드 동작 |
|---|---|
| 섭외요청 문자·이메일 | 발송 안 함 — `sendEngagementSms/Email` 중앙 차단 (기록·링크 생성은 유지) |
| 재안내(리마인드) | 액션 거부 (발송 그 자체라 건별 명시 거부 — 이력 왜곡 방지) |
| 수락서 송신 | 액션 거부 + 버튼 숨김 (포털 서명 흐름의 시작이라 통째로 닫음) |
| 수동 섭외 완료 | 유지 — 라이트 모드의 기본 확정 경로 |
| 섭외 이력 로그 | 유지 (수동 처리 이벤트로 기록) |
| 비용·지급 메뉴 | 닫음 — 페이지 redirect + 액션 거부 + export 403 + 사이드바 숨김 |
| 전문가 풀·일괄 등록·중복 경고·순위·평점·메모 | 전부 유지 |

## 민감정보 원칙 (§5 완화 없음)

- **주민등록번호**: 제공하지 않는다. 권한 자체가 전문가 본인 키페어 재래핑으로
  생기므로 미가입 전문가에게는 기술적으로도 성립하지 않는다.
  라이트라는 이유로 기업이 번호를 직접 입력·보관하는 경로를 열지 않는다(Hard NO).
- **서류**: 출처 기반 열람 유지 — 기업이 올린 서류(`uploaded_by_tenant_id`)는
  올린 기업만 활성 관계 동안 열람. 전문가가 claim하면 소유권·grants는 본인에게.
- **계좌·통장사본**: 지급 단계가 없으므로 수집 근거가 없다. 열람 게이트(지급
  단계)는 그대로 두어 사실상 잠긴다.
- **투명성**: 라이트에서 전문가 알림이 필요한 접근(주민번호 조회·타사 서류
  열람)이 발생하지 않으므로 모순 없음. claim 시 본인 열람 이력 소급 공개는
  기존 로그로 충족.
