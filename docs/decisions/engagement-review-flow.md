# 섭외 프로세스 고도화 — 리스트 작성 · 내부 검토 · 발주처 검토 · 후보 조정 · 품의 자동작성

- 상태: **승인 (2026-11-07, 기본값 6항목 + 보정 2항목 포함)** — 1단계 구현 착수 (기획 지시 2026-11-07, 10항목)
- 설계문서 매핑: 4장(전문가 신원·열람), 5장(민감정보), 7장(전자결재), 8장(워크플로우), 14장(AI 경계)
- 소속 축: `experts`(주) ↔ `approvals`(품의) ↔ `operations`(프로젝트) — 연동 로직은 lib/integrations/
- 데이터: 전부 테넌트 격리(tenant_id + RLS). 예외는 AI 이력 요약(전문가 전역, §4 참조)

## 1. 새 흐름 (프로젝트 탭 순서)

```
섭외후보 등록 → 리스트 작성 → 발주처 검토 → 섭외후보 조정 → 승인 목록 및 섭외 진행 → 섭외 확정 → 지급 품의 → 리뷰 → 참여율 배분
   (기존)        (신규 01)      (신규 02)      (신규 03)          (기존 05)
```

- `projects.engagement_stage`에 세 값을 추가한다: `list_review`(내부 검토 중) · `client_review`(발주처 검토 중) · `adjusting`(후보 조정 중).
  기존 `assigning → plan_review → plan_approved → requesting …`은 그대로이고, 그 앞에 끼워 넣는다.
- **섭외후보 등록 탭의 '품의' 버튼은 없어진다.** 품의는 섭외후보 조정 탭의 '섭외 품의서 자동 작성 및 송신'만 만든다.
- 각 단계는 **건너뛸 수 있다**(발주처 검토가 필요 없는 사업). 단계 건너뛰기는 버튼으로 명시하고 로그를 남긴다.
- 모든 송신(내부 검토 요청·발주처 링크·품의)은 **미리보기 → 확인 → 송신** 2단계(§14-3·04번).

## 2. 데이터 모델 (전부 새 표 · 추가 전용 · 멱등)

### 1단계 (마이그레이션 0012)
- `expert_qualification_memos` — 자격메모. `tenant_id, expert_id, project_id(null 허용), position_id(null), body(≤500), created_by, created_at`.
  테넌트 격리, 전문가 본인 비노출. 프로젝트를 넘어 전문가별로 누적 → '자격메모 이력 보기'.
- `expert_resume_summaries` — AI 이력 요약. `expert_id, document_id(expert_documents), summary, model, prompt_version, source_kind(pdf/image/docx), status(ready/failed/unsupported), created_at`.
  **전역 표**(전문가 소유, 문서 1건당 1요약). 열람은 이력서 열람 규칙과 같다(§4 개정). 전문가 본인도 자기 요약을 볼 수 있다.
- `expert_documents_select` RLS 개정 — **`document_type='resume'`는 활성 전문가 링크·허용(grants) 없이도 자사 임직원(전문가 role 제외)이 열람**. 열람은 종전처럼 전건 `expert_document.view` 감사로그. 통장사본·신분증·서명은 변경 없음.

### 2단계 (0013)
- `candidate_lists` — 섭외 후보 리스트 문서. `tenant_id, project_id, revision, status(drafting/internal_requested/internal_done/client_sent/client_replied/adjusting/submitted/superseded), created_by, submitted_at…`
- `candidate_list_entries` — 리스트 행(세션 × 후보). `list_id, slot_id, position_id, expert_id, rank, unit_fee_online/offline(스냅샷), memo_count`.
  리스트의 **내용은 등록 탭의 자리(engagement_slot_positions)에서 가져오고**, 검토 요청 시점에 스냅샷을 뜬다(검토자가 본 것과 이후 수정이 섞이지 않게).
- `candidate_list_reviews` — 내부 검토. `list_id, reviewer_user_id, status(requested/commented/done), requested_by, requested_at, done_at`.
- `candidate_list_review_comments` — 검토 의견. `review_id, entry_id(null=전체 의견), body, created_at`.

### 3단계 (0014)
- `client_review_links` — 발주처 웹문서 링크. `tenant_id, project_id, list_id, token_hash, password_hash, expires_at, revoked_at, open_count, last_opened_at, created_by`.
  경로는 예약 글자 **`/l/{token}`**(list). 비밀번호는 서버 해시(scrypt) 저장, 5회 틀리면 15분 잠금, 성공 시 서명 쿠키(링크 범위, 2시간).
- `client_review_responses` — 발주처 회신. `link_id, list_id, round, respondent_name(선택), general_comment, submitted_at, ip_hash`.
- `client_review_response_items` — 후보별 의견. `response_id, entry_id, opinion(ok/replace/hold), comment`.

### 4단계 (0015)
- `approval_attachments` — 품의 첨부(일반). `approval_id, kind(client_review_response/internal_review/file), ref_id, title, body_text, storage_path(null), created_at`.
  결재 상세(plan-review-panel)에 '첨부' 섹션으로 표시. 발주처 회신·내부 검토 의견은 **본문 요약 + 첨부 원문** 둘 다 간다(10번).
- `engagement_plans.candidate_list_id` 컬럼 추가 — 어느 리스트에서 올라온 품의인지.

## 3. 화면·동작

### 리스트 작성 탭 (01·04·07·08)
- 세션별 표: 코드넘버 · 순위 · 후보(이름·전문분야·경력) · 단가 · **자격메모(3칸 + 추가)** · 버튼 3개(**이력서 열람 / AI 이력 요약 / 자격메모 이력 보기**).
- 자격메모 3개 미만인 후보가 있으면 '내부 검토 요청' 버튼이 비활성(규칙 문구 표시). 담당자(프로젝트 팀)가 쓴다.
- 하단 **내부 검토** 버튼 → 미리보기(검토자가 볼 문서 그대로) → 검토자 선택(기본: 이사·대표 등급 전원 체크, 해제 가능) → 요청.
  검토자에게 알림(내 업무 + 쪽지 자동 발송 "내부 검토 요청"), 검토자는 같은 탭에서 후보별/전체 의견을 적고 '검토 완료'.
  전원 완료 또는 담당자의 '내부 검토 마감'으로 `internal_done`.

### 발주처 검토 탭 (02·04)
- 내부 검토 완료 리스트를 발주처용 문서로 **미리보기**(회사 로고·이름 중심 §16) → '링크 만들기': 비밀번호 설정(직접 입력 또는 자동 생성), 만료일(기본 14일) → URL + 비밀번호 표시·복사.
  **전달은 담당자가 한다**(문자·메일 자동 발송은 후속 — 발주처 담당자 연락처 표를 아직 두지 않았다).
- 발주처 웹문서 `/l/{token}`: 비밀번호 입력 → 세션별 후보 카드(이름·전문분야·경력 요약·강의분야·소속). **연락처·단가·이력서는 보이지 않는다.**
  후보별 의견(적합/교체 요청/보류 + 메모) + 하단 전체 요청사항 → **요청/회신 하기** → 탭에 회신 라운드로 저장, 담당자에게 알림.
- **발주처가 '요청/회신 하기'를 누르면 그 링크는 자동 회수된다**(revoked_at 기록, 재접속 시 "회신이 완료된 링크입니다" 안내) — 기획 보정 2026-11-07. 추가 의견이 필요하면 담당자가 리스트를 고쳐 **새 링크(새 라운드)** 를 만든다.

### 섭외후보 조정 탭 (03·05·10)
- 좌: 내부 검토 리스트 + 의견 / 우: 발주처 회신(후보별 의견 배지). 가운데에 기존 등록 탭의 편집 부품(후보 교체·순위·단가)을 그대로 둬 수정한다.
- **섭외 품의서 자동 작성 및 송신** → 미리보기: 제목·본문(세션별 후보·단가·자격메모 요약·내부 검토 의견 요약·발주처 회신 요약) + 첨부(발주처 회신 원문·내부 검토 의견) → 결재선 확인 → 송신.
  내부적으로는 기존 `submitEngagementPlan`을 호출하되 note·첨부를 채운다. 결재권자의 직접 조정(순위·제외·단가, 기존 plan_review_changes)과 조정 요청사항은 그대로 → 승인되면 기존 '승인 목록 및 섭외 진행' 탭으로 흐른다(05).

### 전문가 목록 · 섭외 후보 검색 (09)
- 각 행에 **이력서 보기 / AI 이력 요약 / 자격메모 이력** 버튼. 이력서가 없으면 '이력서 없음'으로 비활성.

### AI 이력 요약 (08)
- 이력서 업로드(전문가 포털·기업 대리 업로드) 직후 서버에서 비동기 생성해 저장, 실패 시 버튼 클릭 때 다시 시도.
- 입력: PDF·이미지는 Anthropic 문서/이미지 입력으로 직접, DOCX는 텍스트 추출 후. **HWP/HWPX는 rhwp(GitHub 공개 HWP 파서)의 문서 해석 기술로 텍스트를 추출**해 요약한다(기획 보정 2026-11-07). 서버 전용 처리, 추출 실패 시 '요약 불가' 안내.
- 출력: 5줄 요약(전문분야·경력 연수·주요 이력·강의/멘토링 경험·자격) + "AI가 요약한 참고 정보, 판단은 사람이" 고지. 프롬프트 버전 관리(`AI_PROMPT_VERSIONS.resume_summary`).
- 경계(§14-1): 요약은 설명용. 섭외 결정·순위·비용 판정에 쓰지 않는다. 호출은 audit_logs.

## 4. 정책 개정 (06) — CLAUDE.md §4·§5 반영 예정

현행: "서류·이력서 = 전문가의 열람 허용(grants)" / "이력서 = 계약기간 내 자유 열람(로그만)".
개정: **이력서는 섭외 목적의 열람을 허가한다** — ① 섭외 후보 검색·등록 ② 리스트 작성 ③ 품의 결재권자. 근거: 등록 전문가는 "여러 기업이 나를 찾아 섭외한다"는 기대로 등록하므로, 이력서 열람은 잠재적 멘토의 이익에 부합한다(§4 전문가 풀 전면 공개 2026-08-22와 같은 논리).
유지: 통장사본·신분증·서명·주민번호는 종전 게이트 그대로. 모든 열람은 감사로그 + 전문가 본인 열람 이력 공개.
**필요 조치**: 전문가 약관·개인정보 동의 문구에 "이력서 섭외 목적 열람" 및 "AI 요약 생성(외부 API 처리)" 명시 — 법적 문구 개정 백로그에 추가.

## 6. 확인 요청 (기본값 제안 — 다르면 알려 주세요)

1. 06 정책 개정(이력서 섭외 목적 열람 + 약관 개정 백로그) — **진행**
2. 발주처 웹문서 노출 범위: 이름·전문분야·경력 요약·강의분야·소속 **O** / 연락처·단가·이력서 **X**
3. 발주처 링크 전달: URL+비밀번호를 화면에 표시해 담당자가 전달(기본). 문자·메일 자동 발송은 후속.
4. 내부 검토자: 이사·대표 등급 전원 기본 체크, 담당자가 조정 가능
5. 자격메모: 후보별 3개 미만이면 내부 검토 요청 불가(서버 강제), 4개 이상 추가 가능
6. AI 이력 요약: PDF·이미지·DOCX 지원, HWP/HWPX는 rhwp 파서로 텍스트 추출 후 요약. 이력서 원문이 Anthropic API(서버 전용)로 전송됨 — 개인정보처리방침 고지 필요
7. 발주처 링크는 '요청/회신 하기' 1회로 자동 회수(재접속 불가). 재검토는 새 링크로.
