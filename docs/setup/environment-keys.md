# 운영 환경변수 설정 가이드

캐스트로그가 외부 서비스와 연결되려면 **키(비밀번호 같은 문자열)** 를 등록해야
합니다. 이 문서는 지금 필요한 세 가지를 다룹니다.

| 키 | 무엇이 켜지나 | 없으면 | 급한가 |
|---|---|---|---|
| `PLATFORM_ADMIN_EMAILS` | 관리자 모드 전환 버튼 | 버튼이 안 보임 | **높음** |
| `ANTHROPIC_API_KEY` | 사용법 도우미 챗봇 + 상담게시판 | 챗봇이 "아직 켜지지 않았습니다" | 중간 |
| `OPINET_API_KEY` | 출장품의 유류비 자동 조회 | 유가를 손으로 입력 | 낮음 |
| `NAVER_MAP_CLIENT_ID`<br>`NAVER_MAP_CLIENT_SECRET` | 출장품의 거리 자동 계산 | 거리를 손으로 입력 | 낮음 |

> **넣은 뒤에는 반드시 확인하세요.** 관리자 모드 → **연동 점검**
> (`castlog.kr/platform-admin/integrations`)에서 버튼 한 번으로 각 연동을 실제
> 호출해 보고, 실패하면 그 API가 돌려준 사유를 그대로 보여 줍니다.

---

## 공통 — 환경변수를 어디에 넣나

캐스트로그는 **Vercel**에 배포됩니다. 키는 코드가 아니라 Vercel에 저장합니다
(코드에 적으면 GitHub에 그대로 올라가 누구나 볼 수 있습니다).

### 넣는 순서 (세 키 모두 동일)

1. 브라우저에서 <https://vercel.com> 로그인
2. 캐스트로그 프로젝트 클릭
3. 상단 **Settings** 탭
4. 왼쪽 메뉴 **Environment Variables**
5. **Key** 칸에 변수 이름, **Value** 칸에 값을 붙여 넣기
6. 적용 범위(Environments)는 **Production · Preview · Development 모두 체크**
7. **Save**

> ⚠️ **저장만 하면 아직 적용되지 않습니다.** 환경변수는 배포 시점에 주입되므로
> 새로 배포해야 반영됩니다. Vercel의 **Deployments** 탭 → 맨 위 배포의 **⋯**
> 메뉴 → **Redeploy** 를 누르면 1~2분 뒤 적용됩니다.

## 1. `PLATFORM_ADMIN_EMAILS` — 관리자 모드 전환

### 왜 필요한가

넥스트랩 직원도 평소에는 **자기 회사(넥스트랩) 테넌트 계정**으로 일합니다.
그러다 다른 회사의 테넌트를 만들거나, 모듈 요청을 승인하거나, 챗봇 상담게시판을
볼 때만 **관리자 모드**로 올라가야 합니다.

이때 문제가 하나 있습니다. 관리자 모드는 **모든 회사의 경계를 넘는 권한**입니다.
그래서 "누가 올라갈 수 있는가"의 명단을 데이터베이스에 두면 위험합니다 —
데이터베이스에 쓸 수 있게 된 공격자가 자기 이메일을 명단에 넣어 스스로를
관리자로 만들 수 있기 때문입니다.

환경변수는 **앱 바깥(Vercel 설정)** 에 있습니다. 앱을 통해서는 고칠 수 없으므로
그 경로가 막힙니다. 이것이 명단을 여기 두는 이유입니다.

### 값 형식

이메일 주소를 쉼표로 구분합니다. 대소문자·앞뒤 공백은 무시됩니다.

```
ceo@example.com
```

여러 명이라면:

```
ceo@example.com,manager@example.com
```

> ⚠️ **캐스트로그에 로그인할 때 쓰는 그 이메일**이어야 합니다. 회사 대표 메일이나
> 평소 쓰는 개인 메일과 다를 수 있으니 짐작으로 넣지 마세요. 로그인한 상태에서
> `castlog.kr/account/admin-mode` 를 열면 **로그인 이메일**이 그대로 표시됩니다.
> 그 값을 복사해서 넣으시면 됩니다.

### 작업 순서

1. 위 **공통** 순서대로 Vercel에 `PLATFORM_ADMIN_EMAILS` 추가
2. Redeploy
3. castlog.kr에 넥스트랩 CEO 계정으로 로그인
4. 화면 **오른쪽 위**, 이메일 왼쪽에 남색 **`관리자 모드`** 버튼이 보이면 성공
5. 누르면 `castlog.kr/platform-admin` 으로 이동합니다
6. 관리자 모드 화면 오른쪽 위 **`기업 모드로`** 버튼으로 원래 자리로 돌아옵니다

### 확인·문제 해결

**먼저 `castlog.kr/account/admin-mode` 를 여세요.** 판정에 쓰이는 값(로그인
이메일 · 명단 등록 여부 · 현재 역할)이 그대로 표시되므로, 그 한 화면으로 원인이
갈립니다.

- **명단에 "등록되지 않음"** → 표시된 로그인 이메일과 환경변수 값이 다릅니다.
  화면의 이메일을 복사해 넣고 Redeploy 하세요. (가장 흔한 원인입니다)
- **버튼이 안 보인다** → 위와 같은 원인이거나 Redeploy 전입니다.
- **눌렀는데 되돌아온다** → 명단에 없는 계정입니다. 조용히 원래 자리로
  보냅니다(존재 여부를 알려 주지 않기 위해서입니다).
- 진입·이탈은 **감사로그**에 남습니다. 관리모드 → 감사로그에서
  `platform_mode.enter` / `platform_mode.exit` 로 확인할 수 있습니다.

## 2. `ANTHROPIC_API_KEY` — 사용법 도우미 챗봇

### 왜 필요한가

화면 오른쪽 아래 **도우미**는 사용자의 질문을 이해하고 답을 만들어야 합니다.
그 언어 능력은 Anthropic(클로드)의 서버가 제공하며, 우리 서버가 그쪽에
요청을 보낼 때 **누구의 요청인지 증명하는 열쇠**가 이 키입니다.

이 키 하나가 두 가지를 함께 켭니다.

1. **도우미 답변** — "수락서는 어디서 보내나요?" 같은 질문에 대한 안내
2. **챗봇 상담게시판** — 대화 중 흘린 불편·오류·이해 실패를 자동으로 분류해
   관리모드 게시판(건의/요청 · FAQ)에 쌓는 기능

키가 없으면 도우미는 **거짓말을 지어내지 않고** "아직 켜지지 않았습니다"라고
답합니다. 다른 기능에는 영향이 없습니다.

### 키 발급 순서

1. <https://console.anthropic.com> 접속 → 회원가입/로그인
   (회사 이메일로 가입하시길 권합니다)
2. 왼쪽 메뉴 **Settings** → **API keys**
3. **Create Key** 버튼
4. 이름은 알아보기 쉽게 (예: `castlog-production`)
5. 만들어진 키(`sk-ant-` 로 시작하는 긴 문자열)를 **바로 복사**
   > ⚠️ 이 화면을 닫으면 키를 **다시 볼 수 없습니다.** 잃어버리면 새로 만들어야
   > 합니다. 안전한 곳(회사 비밀번호 관리도구)에 함께 보관하세요.
6. **결제 등록** — 왼쪽 메뉴 **Billing** 에서 카드 등록 후 크레딧 충전.
   등록하지 않으면 호출이 거부됩니다.

### 비용 감각

도우미는 짧은 문답용으로 맞춰 두었습니다(답변 최대 700 토큰, 분류 250 토큰).
직원 20명이 하루 몇 번씩 물어보는 정도라면 **월 몇 천 원~수만 원** 선입니다.
Anthropic 콘솔의 **Usage** 에서 실제 사용량을 볼 수 있고, **Billing → Limits**
에서 월 상한을 걸어 두면 예상 밖 지출을 막을 수 있습니다.

### 작업 순서

1. 위 **공통** 순서대로 Vercel에 `ANTHROPIC_API_KEY` 추가 (값은 `sk-ant-...`)
2. Redeploy
3. castlog.kr 로그인 → 오른쪽 **아래** 떠 있는 **도움말** 버튼
4. "전문가 섭외는 어떤 순서로 하나요?" 를 눌러 답이 오면 성공

### 확인·문제 해결

- **"아직 켜지지 않았습니다"** → 키가 등록되지 않았거나 Redeploy 전입니다.
- **"AI 응답 오류 (401)"** → 키가 잘못되었거나 삭제되었습니다. 새로 발급하세요.
- **"AI 응답 오류 (429)"** → 크레딧이 없거나 한도를 넘었습니다. Billing 확인.
- 상담게시판은 `castlog.kr/platform-admin/help-board` (관리자 모드에서 접근).
  대화를 몇 번 나눈 뒤 들어가면 항목이 쌓입니다. **연습모드에서 나눈 대화는
  게시판에 올라오지 않습니다** — 연습은 운영 신호가 아니기 때문입니다.

### 개인정보 관련 (알아 두실 것)

- 도우미에게는 **회사 이름·직급·사용 모듈·현재 화면 경로**만 전달됩니다.
- **실제 프로젝트명·전문가 이름·금액은 전달되지 않습니다.**
- 상담게시판에는 **대화 원문이 저장되지 않습니다.** 정리된 제목·요약과 화면
  경로만 남습니다.
- 도우미는 결재 승인·지급 금액 같은 **업무 판단을 대신하지 않습니다**
  (CLAUDE.md §14-1).

## 3. `OPINET_API_KEY` — 출장품의 유류비 자동 조회

### 왜 필요한가

**전자결재 → 출장품의**에서 유류비를 계산할 때, 오늘의 기름값이 필요합니다.
오피넷(한국석유공사 유가정보시스템)은 **전국 평균 판매가**를 공개 API로
제공합니다. 이 키가 있으면 휘발유·경유·LPG 단가가 **자동으로 채워집니다**.

키가 없어도 출장품의는 **그대로 동작합니다.** 다만 단가를 담당자가 직접
입력해야 하고, 그 값이 맞는지 아무도 검증해 주지 않습니다. 자동 조회는
"이 숫자는 오늘 오피넷 값"이라는 근거를 남기는 의미가 큽니다.

> 참고: 거리 자동 계산은 별도로 **네이버 지도 키**(`NAVER_MAP_CLIENT_ID`,
> `NAVER_MAP_CLIENT_SECRET`)를 씁니다. 유가와 거리는 서로 독립이라 하나만
> 설정해도 그 부분만 자동으로 채워집니다.

### 키 발급 순서

1. <https://www.opinet.co.kr> 접속
2. 상단 메뉴에서 **정보제공** → **Open API** (또는 사이트 하단 `Open API` 링크)
3. **API 키 발급 신청** — 회원가입이 필요합니다
4. 신청서에 사용 목적을 적습니다
   (예: "사내 출장비 정산 시스템의 유류비 자동 계산")
5. 승인되면 **개인 인증키(문자열)** 가 발급됩니다
   - 즉시 발급되는 경우도 있고, 담당자 검토로 1~2일 걸리는 경우도 있습니다
6. 발급된 키를 복사

### 작업 순서

1. 위 **공통** 순서대로 Vercel에 `OPINET_API_KEY` 추가
2. Redeploy
3. castlog.kr 로그인 → **전자결재 → 출장품의**
4. 연료 종류를 고르면 단가가 자동으로 채워지면 성공

### 확인·문제 해결

- **"오피넷 API 키(OPINET_API_KEY)가 설정되지 않았습니다"** → 등록 전이거나
  Redeploy 전입니다.
- **"오피넷이 유가를 반환하지 않았습니다(키 권한 확인)"** → 키는 등록됐지만
  해당 API 사용 권한이 없습니다. 오피넷에서 **평균판매가격 API** 사용 신청이
  되어 있는지 확인하세요.
- **"오피넷 응답 오류 (HTTP 4xx)"** → 키 문자열이 잘못되었을 가능성이 큽니다.
- 실패해도 화면은 **손 입력으로 넘어갑니다** — 품의 작성 자체가 막히지는
  않습니다.

## 4. `NAVER_MAP_CLIENT_ID` · `NAVER_MAP_CLIENT_SECRET` — 출장 거리 자동 계산

### 왜 필요한가

출장품의의 유류비는 **거리 ÷ 연비 × 유가**로 계산합니다. 오피넷이 '유가'를
채운다면, 네이버 지도는 '거리'를 채웁니다. 출발지·도착지 주소를 넣으면 실제
**자동차 주행 거리(km)** 를 가져옵니다.

직선거리가 아니라 주행 거리라는 점이 중요합니다. 결재선에 올라가는 숫자는
"지도가 알려 준 실제 경로"여야 근거가 됩니다.

이 연동은 네이버 API 두 개를 **연달아** 씁니다.

1. **Geocoding** — 주소("서울특별시청")를 좌표로 바꿉니다
2. **Directions** — 좌표 두 개 사이의 주행 거리를 구합니다

둘은 네이버에서 **각각 따로 이용 신청**하는 상품입니다. 하나만 신청하면
절반에서 막히므로, 아래에서 둘 다 신청하시는 것이 중요합니다.

키가 없어도 출장품의는 동작합니다 — 거리를 손으로 넣으면 됩니다.

### 키 발급 순서

네이버 지도 API는 **네이버 클라우드 플랫폼(NCP)** 에서 발급합니다.
(예전 'NAVER Developers'가 아닙니다 — 개인용 오픈API와 다른 서비스입니다.)

1. <https://www.ncloud.com> 접속 → **회원가입 / 로그인**
   - 사업자 회원으로 가입하시면 세금계산서 발행이 됩니다
2. **결제수단 등록** — 마이페이지 → 결제수단 관리에서 카드 등록
   > 무료 한도가 넉넉하지만(월 수만 건 수준), 결제수단이 없으면 API 이용
   > 신청 자체가 막힙니다
3. 상단 **Services** → **Application Services** → **Maps** 선택
   (검색창에 `Maps` 를 쳐도 됩니다)
4. **이용 신청하기** 클릭
5. **Application 등록**
   - Application 이름: `castlog` 처럼 알아보기 쉽게
   - **Service 선택에서 아래 둘을 반드시 체크**
     - ☑ **Geocoding** (주소 → 좌표)
     - ☑ **Directions 5** (길찾기·거리)
   - 나머지(Web Dynamic Map 등)는 쓰지 않으므로 체크하지 않아도 됩니다
6. 등록을 마치면 **Application 목록**에 항목이 생깁니다
7. 해당 Application의 **인증정보** 버튼을 누르면 두 값이 보입니다
   - **Client ID** → `NAVER_MAP_CLIENT_ID`
   - **Client Secret** → `NAVER_MAP_CLIENT_SECRET`
   (Secret은 **인증정보** 화면에서 언제든 다시 볼 수 있습니다)

### 작업 순서

1. 위 **공통** 순서대로 Vercel에 **두 개** 모두 추가
   - `NAVER_MAP_CLIENT_ID` = Client ID
   - `NAVER_MAP_CLIENT_SECRET` = Client Secret
2. Redeploy
3. 관리자 모드 → **연동 점검** → **연동 점검 실행**
   - `네이버 지도 (거리)` 가 **정상**이고 `서울특별시청 → 경기도청 ○○km` 가
     보이면 성공입니다
4. 실제 사용: **전자결재 → 출장품의** → 출발지·도착지 입력 →
   **자동 계산** 버튼 → 거리·유가가 함께 채워집니다

### 확인·문제 해결

화면에 나오는 문구별로 원인이 다릅니다.

| 문구 | 원인 | 조치 |
|---|---|---|
| `네이버 지도 키(...)가 설정되지 않았습니다` | 환경변수 미등록 또는 Redeploy 전 | Vercel 확인 후 Redeploy |
| `네이버 지도 인증 실패 (HTTP 401/403)` | 키가 틀렸거나 **Maps 이용 신청이 안 됨** | 인증정보 재확인 + Geocoding 신청 여부 확인 |
| `‘○○’ 주소를 찾지 못했습니다` | 주소 표기 문제 | 도로명주소나 건물명으로 다시 입력 |
| `네이버 길찾기 응답 오류 (HTTP 4xx)` | **Directions 5 이용 신청 누락**이 가장 흔함 | NCP Maps에서 Directions 5 체크 후 저장 |
| `두 지점 사이 자동차 경로를 찾지 못했습니다` | 실제로 차로 갈 수 없는 구간(섬 등) | 거리를 직접 입력 |

> **게이트웨이 호스트에 대해**: 네이버는 Maps API 주소를 옮긴 이력이 있어
> 계정마다 열려 있는 호스트가 다릅니다. 캐스트로그는 신규(`maps.apigw.ntruss.com`)
> → 구(`naveropenapi.apigw.ntruss.com`) 순으로 자동 재시도합니다. 특정 호스트만
> 써야 한다면 `NAVER_MAP_API_HOST` 환경변수로 고정할 수 있습니다.

### 비용

Geocoding·Directions 모두 **월 무료 제공량**이 있고, 출장품의는 담당자가 버튼을
누를 때만 호출합니다(한 번 누르면 지오코딩 2회 + 길찾기 1회). 사내 출장 정산
수준에서는 무료 범위를 넘기기 어렵습니다. NCP 콘솔의 **My Charge** 에서 실제
사용량을 확인할 수 있습니다.

## 5. Supabase 인증 URL 설정 — 비밀번호 설정·찾기 링크

이건 환경변수가 아니라 **Supabase 대시보드 설정**입니다. 그런데 이게 틀리면
계정을 받은 사람이 서비스에 들어올 수 없으므로 여기 함께 적어 둡니다.

### 왜 필요한가

캐스트로그가 보내는 두 종류의 메일이 이 설정에 걸려 있습니다.

- 대표 계정 발급 시 **비밀번호 설정 링크** (관리모드에서 테넌트 생성 시 자동 발송)
- 로그인 화면의 **비밀번호 찾기** 링크

두 링크 모두 "Supabase에서 토큰을 확인한 뒤 → 캐스트로그로 돌아오는" 구조입니다.
돌아올 주소(`https://castlog.kr/auth/callback`)가 Supabase에 등록되어 있지 않으면,
Supabase는 **거부하지 않고 조용히 Site URL로 바꿔치기합니다.** 그래서 메일은 정상
발송되고 링크도 정상으로 보이는데, 받는 사람이 누르면 엉뚱한 곳으로 갑니다.

실제로 그렇게 나간 적이 있습니다 — Site URL이 scheme 없이 `castlog.kr`로 저장되어
있어서, Supabase가 그것을 자기 도메인의 하위 경로로 읽고
`{"error":"requested path is invalid"}` 를 띄웠습니다.

### 작업 순서

1. [supabase.com](https://supabase.com) 로그인 → 캐스트로그 프로젝트 선택
2. 왼쪽 메뉴 **Authentication** → **URL Configuration**
3. **Site URL** 을 `https://castlog.kr` 로 설정합니다.
   `https://` 를 반드시 포함하세요. 이것이 빠지면 위 증상이 그대로 재현됩니다.
4. **Redirect URLs** 에 아래를 추가합니다 (Add URL 버튼):
   - `https://castlog.kr/**`
   - (프리뷰 배포에서도 테스트하신다면) `https://*.vercel.app/**`
5. **Save** 를 누릅니다. 재배포는 필요 없습니다 — Supabase 쪽 설정입니다.

### 확인

관리자 모드 → 가입 기업 목록에서 아무 회사의 **‘비밀번호 설정 메일’** 버튼을
누릅니다.

- 버튼 옆에 `○○@… 로 보냈습니다` → 정상입니다.
- `Supabase가 복귀 주소를 '…'로 바꿨습니다` → 아직 3·4번이 반영되지 않은 것입니다.
  이 경우 **메일은 보내지 않습니다.** 깨진 링크를 받은 고객은 우리 서비스가 고장
  났다고 판단하므로, 보내는 것보다 안 보내고 원인을 남기는 편이 낫습니다.

받은 메일의 링크를 눌렀을 때 캐스트로그 비밀번호 재설정 화면이 뜨면 끝입니다.

## 6. 캐스트로그 발송 계정 (SMS 방식 b) — `PLATFORM_SOLAPI_API_KEY` 외 2종

> **현재 보류 중입니다.** 아래 환경변수를 설정하기 전에는 기업 설정 화면에
> b 방식 선택지가 나타나지 않습니다(자사 계정 방식만 보임). 제공을 시작하기로
> 결정하면 이 절의 변수 3종을 넣고 Redeploy 하는 것으로 끝납니다 — 코드 수정
> 불요.

### 왜 필요한가

기업이 SMS 발송 방식을 둘 중 고를 수 있습니다:

- **a. 자사 계정** — 기업이 직접 솔라피에 가입해 자사 키를 등록 (기존 방식)
- **b. 캐스트로그 계정** — 공급자 가입 없이 캐스트로그(넥스트랩)의 솔라피 계정으로 발송

b를 쓰려면 캐스트로그 솔라피 자격증명이 서버에 있어야 합니다. DB에는 저장하지
않고 **환경변수로만** 둡니다 — 테넌트 데이터가 탈취돼도 플랫폼 키는 나가지 않습니다.

| 변수 | 값 |
|---|---|
| `PLATFORM_SOLAPI_API_KEY` | 넥스트랩 솔라피 API Key |
| `PLATFORM_SOLAPI_API_SECRET` | 넥스트랩 솔라피 API Secret |
| `PLATFORM_SMS_ACCESS_CODE` | 기업이 b 방식을 신청할 때 입력할 이용코드 (담당자가 정해서 기업에 전달) |

이용코드는 최초 1회만 검증하고 승인 시각만 저장합니다 — **코드를 나중에 바꿔도
이미 승인된 기업은 계속 사용합니다.** 신규 기업 유입만 새 코드로 통제됩니다.

### 운영 절차 — 기업이 b를 신청하면

1. 기업 대표가 설정 > SMS 설정에서 '캐스트로그 계정으로 발송' 선택 →
   자사 발신번호 + 이용코드 입력 → 저장.
2. **캐스트로그 담당자가 그 발신번호를 넥스트랩 솔라피 계정에
   ‘타인(타사) 명의 발신번호’로 등록합니다.** 솔라피 콘솔 → 발신번호 관리 →
   타인 명의 등록(서류 심사). 필요한 서류 — 그 기업으로부터 받습니다:
   - **발신번호 사용 위임장(사용 동의서)** — 그 기업이 넥스트랩에게 자사
     번호로의 발송을 위임한다는 문서 (기업 직인)
   - 그 기업의 **사업자등록증 사본**
   - 그 번호의 **통신서비스 이용증명원** (통신사에서 발급)

   ⚠️ ARS 인증은 **계정 명의자 본인 번호**용 절차입니다. 타사 번호를 기업
   담당자의 ARS 협조로 우회 등록하는 것은 명의를 속이는 셈이 되므로 하지
   않습니다 — 반드시 위 서류 기반 절차로 등록합니다. 발신번호 사전등록제
   (전기통신사업법 제84조의2)가 이 절차를 공식적으로 예정하고 있어, 서류를
   갖춘 타사 명의 등록은 합법적인 정상 경로입니다.
3. 등록 완료 후 기업이 'SMS 연결 상태'에서 테스트 발송으로 확인합니다.

발송 요금은 넥스트랩 솔라피 계정에 청구됩니다. 사용량은 테넌트별로 계측되므로
(tenant_usage_metrics) 필요 시 계약에 반영할 수 있습니다.

### 법적 유의사항 (b 방식 운영 전 확인)

- **발신번호 표시 문제는 없습니다** — 서류로 위임받아 등록한 타사 명의 번호는
  발신번호 거짓표시(변작)가 아닙니다. 제도가 대행 발송을 전제로 만든 절차입니다.
- **위법 발송 책임은 넥스트랩 계정으로 귀속됩니다.** b 기업이 스팸을 보내면
  제재(번호 차단·계정 정지)가 넥스트랩 솔라피 계정에 떨어집니다. 광고성 발송
  강제장치(미동의 제외·(광고) 표기·수신거부 링크·야간 차단)는 시스템이 이미
  강제하며, 이용코드 승인제가 아무나 못 들어오게 하는 통제의 일부입니다.
- **규모가 커지면 ‘문자 재판매사업자’ 해당 여부를 검토하세요.** 여러 기업의
  문자를 대신 발송하는 형태가 커지면 대량문자 전송자격인증제(2024~, 방통위·KAIT)
  대상인 재판매사업자로 볼 여지가 생깁니다. b 이용 기업이 소수일 때는 SaaS 부가
  기능 수준이지만, 본격 확대 전에 솔라피(공식 인증 사업자)와 법률 자문으로
  신고·인증 필요 여부를 확인해 두는 것이 안전합니다.

## 정리 — 지금 하실 일

| 순서 | 작업 | 걸리는 시간 |
|---|---|---|
| 1 | Vercel에 `PLATFORM_ADMIN_EMAILS` 추가 → Redeploy | 5분 |
| 2 | Anthropic 콘솔에서 키 발급 + 결제 등록 → Vercel 추가 → Redeploy | 15분 |
| 3 | 오피넷 Open API 키 신청 (승인 대기 가능) → Vercel 추가 → Redeploy | 신청 10분 + 대기 |
| 4 | NCP 가입·결제등록 → Maps(Geocoding + Directions 5) 신청 → Vercel 추가 → Redeploy | 20분 |
| 5 | Supabase → Authentication → URL Configuration (Site URL·Redirect URLs) | 3분 |
| 6 | 관리자 모드 → **연동 점검** 에서 전체 확인 | 1분 |

승인 대기가 있을 수 있는 3번은 **먼저 신청만 걸어 두시길** 권합니다.
모두 넣은 뒤에는 6번으로 한 번에 확인하시면 됩니다.

5번(Supabase URL 설정)은 다른 키와 성격이 다릅니다 — 이것이 틀리면 **계정을 받은
고객이 아예 로그인하지 못하므로**, 신규 기업을 받기 전에 먼저 맞춰 두세요.
